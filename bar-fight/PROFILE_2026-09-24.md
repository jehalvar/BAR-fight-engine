# One short replay: engine profile

Feature pre-frame transforms are the clearest substantial region to investigate
in this diagnostic: **10.746 seconds inside 60.714 seconds of measured Sim time**.
The source shows an every-frame pass over all map features. This identifies work
to inspect; it does not establish how much can safely be removed.

## Method

One complete 6:25 public Supreme Isthmus v2.1 replay:
`8d06b06aa8e31c2640d10862098f8ccb`. Existing verified custom 75% executable,
SHA-256 `788a964282f9dc83f56a1c7e3e0ae6ca3fd190ac09aacb18e667508923987cc1`.
There was no new source build and no medium or long replay run.

A separate diagnostic widget enabled `debug 1 0`, retaining the production
collector and unchanged frame-checksum observer. It read raw profiler totals
at frame zero and at widget shutdown. Reported values subtract the frame-zero
baseline from shutdown totals. The interval includes post-game work through
widget shutdown. The name list is refreshed periodically; raw totals are current.
There were 45 names at the baseline and 83 at shutdown.

The unprivileged run used two reserved CPUs, a 6 GiB memory limit and a 900-second
runtime limit, protected by a restoration timer. Total child-engine wall time
was 163.579 seconds, including startup. The run used a fresh private archive
cache. **This is attribution evidence, not an optimisation benchmark**: profiling
adds overhead and there is no matched profile-on/off pair.

## Main timing regions

| Region | Measured seconds | Interpretation |
| --- | ---: | --- |
| Sim | 60.714 | Parent simulation region |
| Sim::Features::UpdatePreFrame | 10.746 | Nested inside Sim; all active features' previous transforms |
| Sim::Script | 9.451 | Nested inside Sim; unit-script processing |
| Sim::Path | 9.158 | Nested inside Sim; map updates account for 8.286 s within this |
| Sim::GameFrame | 8.222 | Nested inside Sim; frame callbacks and garbage collection |
| Sim::Unit::MoveType | 7.407 | Nested inside Sim; movement processing |
| Update | 7.255 | Unsynced update phase, separate from Sim |
| Update::WorldDrawer | 5.665 | Nested inside Update |
| Draw | 5.332 | Render-side work, excluding Update |

`CFeatureDrawerBase::Update` accounted for 3.826 seconds within world-drawer
updates. The proposed GPU uniform-packing guard removes only a subset of work
within relevant drawer updates; none of these whole-region totals is its
predicted saving.

The thread-pool timers report 27.211 seconds for AddTask, 24.916 for WaitFor and
23.946 for RunTask. These overlap and **are not three independent overheads**.
WaitFor can execute task work itself. Lua timings also cross other regions.
The profiler's own AddTime region recorded 2.449 seconds, further illustrating
why these measurements cannot serve as an unbiased speed comparison.

## Correctness and restoration

- All three production capture streams matched exactly: 28 telemetry rows,
  434 team-stat rows and 2,815 observation rows.
- All 11,415 real frame checksums, frames 0–11,414, matched the official control.
- The unchanged validator passed real GameOver, engine identity, no-desync/error
  checks and all 112 footer measurements across 16 teams.
- The diagnostic unit stopped, and all twenty production worker CPU allocations
  were restored. Worker PIDs and restart counts did not change during the test.

This establishes that the diagnostic preserved this replay's captured data. It
does not validate any proposed optimisation or establish a whole-fleet gain.
Production remains on the official engine with the existing 75% setting.
